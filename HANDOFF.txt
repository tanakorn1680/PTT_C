HANDOFF — พอร์ตเกม Prototype (PC 2009) เป็น APK native ด้วยการแปลง DLL เป็น C
(ไฟล์นี้ไว้ส่งต่อให้ AI ตัวอื่นทำต่อ — อัปเดตทุกครั้งที่ส่งงานใหม่)
อัปเดตล่าสุด: 2026-10-24 (รอบที่ 8)

== เป้าหมาย ==
- ทำ APK Android (arm64) ที่รัน Prototype (Radical Entertainment, 2009) แบบ native
  ด้วยแนวทาง static recompilation เหมือนโปรเจกต์ codepdbh/nfsu2-recompiled
  (x86 -> C ด้วย pcrecomp -> compile ด้วย NDK; กราฟิก D3D9 -> Vulkan ผ่าน DXVK)
- ผู้ใช้มีไฟล์เกมของแท้ และต้องการประสิทธิภาพสูงสุด (ห้ามใช้ตัวจำลอง/emulator เช่น Winlator, Box64)

== ข้อจำกัดของผู้ใช้ / วิธีทำงาน ==
- มีแต่มือถือ Android ไม่มีคอม ใช้ GitHub Actions (repo ต้อง private)
- สื่อสารภาษาไทย
- ส่งงานเป็น ZIP เฉพาะไฟล์ที่เปลี่ยน โครงโฟลเดอร์ตรงกับ root ของ repo (แตกทับได้เลย)
- ไม่ต้องทดสอบ/ทำอะไรเกินจำเป็น; บันทึกความคืบหน้าไว้ในไฟล์นี้ทุกครั้ง
- ผู้ใช้เปลี่ยนชื่อ DLL เป็น game/engine.dll ใน repo (workflow เลือก .dll ที่ใหญ่สุดใน game/)
  ในโฟลเดอร์เกมจริงต้องใช้ชื่อเดิม (prototypeenginef.dll)
- AI ที่ทำงานในแชตไม่มีเน็ต (ดึง pcrecomp/NDK ไม่ได้) => ทดสอบจริงได้แค่บน GitHub Actions
  ผู้ใช้เป็นคนรัน workflow แล้วส่ง artifact "lift-report" กลับมา

== ข้อมูลที่ยืนยันแล้ว (จากการตรวจไฟล์) ==
- prototypef.exe = ตัวเปิด (launcher) โค้ดจริงราว 8KB; โหลด DLL ของ engine แล้วเรียก export
  (EngineInitialize, EngineService, EngineTerminate, EngineWindowFocus, EngineMouseService,
   EngineKeyboardService, MainWin32). ชื่อ DLL ที่ exe โหลดยังไม่ยืนยัน (เดาจากสตริง "f.dll")
  แนวทางที่เสนอ: ไม่ lift exe แต่เขียน launcher ใหม่ฝั่ง host เรียก export เหล่านี้เอง
- prototypeenginef.dll: PE32 x86, 20.2MB, build 2009-04-22, MSVC 2005 (MSVCR80), ไม่ถูกห่อ/เข้ารหัส,
  ไม่พบสตริง SecuROM/StarForce/Steam, ไม่ใช่ large-address-aware, มี relocation table, image base 0x10000000

  binkw32.dll (วิดีโอ Bink ปิดซอร์ส -> ต้อง stub/ข้ามบน Android)
- Scaleform GFx (UI) ลิงก์อยู่ใน DLL, มีสคริปต์ Lua ในตัวเกม, .text ราว 14MB

== งานที่ทำในรอบที่ 8 (ส่งในซิปนี้) ==

  เลยกฎเดิมอาจตัด export ที่อยู่กลางฟังก์ชันอื่นทิ้ง = ขาด symbol ตอนรัน) workflow ส่ง "$DLL" / "$CRT" ให้แล้ว => จำนวนฟังก์ชันของ msvcr80 อาจมากกว่า 2,378 เล็กน้อย
- patches/ptt_lifter_ext*.py: เพิ่ม `bsr` 32-bit (ZF ตามค่าต้นทาง, ปลายทางไม่เปลี่ยนถ้าเป็น 0) และ `repz ret`/`rep ret` = `ret` (+ เคส difftest 2 เคส: bsr.mem, bsr.zero)
  ยังไม่ทำ fcmovb/fcmovnbe (ต้องใช้ตัวสร้างเงื่อนไขของ lifter) และ fisttp (SSE3) — 3 จุด ปล่อยให้ RECOMP_UNIMPL ดังชัดถ้าเกมชน
- scripts/full_compile.sh: เพิ่ม -fPIC
- ไม่ต้องรัน workflow เพิ่มเพื่อวัดอะไรอีก; รอบถัดไปที่รัน CI คือรอบ build APK จริง (stage 2)

== ขั้นต่อไปที่วางไว้ (stage 2: โครง Android) ==
1) สร้างโครง Android จาก nfsu2-recompiled/android (guest_memory/guest_runtime/guest_*.inc/d3d9_bridge/main.cpp, ~490KB ซอร์ส) ปรับเป็น:
   - โหลด 2 โมดูล: msvcr80 (base 0x78130000) ก่อน แล้ว engine DLL (0x10000000); relocation + IAT; รัน DllMain ของ msvcr80 ก่อน
   - import ของ Prototype ที่ชี้ msvcr80 ผูกกับ export ของโมดูล guest (upstream มี isGuestModule อยู่แล้ว)
   - HLE kernel32 ที่ขาด ~96 ชื่อ (ดู docs/msvcr80_imports.txt + docs/prototype_imports.txt), waveOut -> AAudio, XInput/ทัช,
     stub binkw32/ws2_32/setupapi/ole/iphlpapi, fiber ด้วยเธรดส่งต่อ machine lock, launcher ฝั่ง host เรียก Engine* exports (ไม่ lift exe)
2) CMake/Gradle: คอมไพล์ gen/ + gen_crt/ (-fPIC, ThinLTO, แฟล็กเดียวกับ scripts/full_compile.sh) + host/arm64_guest.h เป็น -include; NDK 28.2.13676358, SDK 35, CMake 3.30.5
3) workflow ใหม่สำหรับ build APK (เซ็นด้วย keystore จาก Secrets, อัปโหลด artifact เฉพาะ APK; repo private)
4) ผู้ใช้ต้องมีไฟล์เกม (asset) บนมือถือ: โฟลเดอร์เกมทั้งหมดที่มี prototypef.exe/prototypeenginef.dll และข้อมูลเกม; ตั้งค่าที่เก็บไฟล์ในแอป
5) (ทางเลือก) fcmov*/fisttp ถ้าเกมชน; override ฟังก์ชันร้อนของ CRT (memcpy/memset/strlen/_CI*) ด้วย native ผ่าน config/overrides.txt
