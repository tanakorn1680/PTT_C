HANDOFF — พอร์ตเกม Prototype (PC 2009) เป็น APK native ด้วยการแปลง DLL เป็น C
(ไฟล์นี้ไว้ส่งต่อให้ AI ตัวอื่นทำต่อ — อัปเดตทุกครั้งที่ส่งงานใหม่)
อัปเดตล่าสุด: 2026-10-24 (รอบที่ 5)

== เป้าหมาย ==
- ทำ APK Android (arm64) ที่รัน Prototype (Radical Entertainment, 2009) แบบ native
  ด้วยแนวทาง static recompilation เหมือนโปรเจกต์ codepdbh/nfsu2-recompiled
  (x86 -> C ด้วย pcrecomp -> compile ด้วย NDK; กราฟิก D3D9 -> Vulkan ผ่าน DXVK)
- ผู้ใช้มีไฟล์เกมของแท้ และต้องการประสิทธิภาพสูงสุด (ห้ามใช้ตัวจำลอง/emulator เช่น Winlator, Box64)

== ข้อจำกัดของผู้ใช้ / วิธีทำงาน ==
- มีแต่มือถือ Android ไม่มีคอม ใช้ GitHub Actions (repo ต้อง private)
- สื่อสารภาษาไทย
- ส่งงานเป็น ZIP เฉพาะไฟล์ที่เปลี่ยน โครงโฟลเดอร์ตรงกับ root ของ repo (แตกทับได้เลย)
- ไม่ต้องทดสอบ/ทำอะไรเกินจำเป็น; บันทึกความคืบหน้าไว้ในไฟล์นี้ทุกครั้ง
- ผู้ใช้เปลี่ยนชื่อ DLL เป็น game/engine.dll ใน repo (workflow เลือก .dll ที่ใหญ่สุดใน game/)
  ในโฟลเดอร์เกมจริงต้องใช้ชื่อเดิม (prototypeenginef.dll)
- AI ที่ทำงานในแชตไม่มีเน็ต (ดึง pcrecomp/NDK ไม่ได้) => ทดสอบจริงได้แค่บน GitHub Actions
  ผู้ใช้เป็นคนรัน workflow แล้วส่ง artifact "lift-report" กลับมา

== ข้อมูลที่ยืนยันแล้ว (จากการตรวจไฟล์) ==
- prototypef.exe = ตัวเปิด (launcher) โค้ดจริงราว 8KB; โหลด DLL ของ engine แล้วเรียก export
  (EngineInitialize, EngineService, EngineTerminate, EngineWindowFocus, EngineMouseService,
   EngineKeyboardService, MainWin32). ชื่อ DLL ที่ exe โหลดยังไม่ยืนยัน (เดาจากสตริง "f.dll")
  แนวทางที่เสนอ: ไม่ lift exe แต่เขียน launcher ใหม่ฝั่ง host เรียก export เหล่านี้เอง
- prototypeenginef.dll: PE32 x86, 20.2MB, build 2009-04-22, MSVC 2005 (MSVCR80), ไม่ถูกห่อ/เข้ารหัส,
  ไม่พบสตริง SecuROM/StarForce/Steam, ไม่ใช่ large-address-aware, มี relocation table, image base 0x10000000
- import: d3d9 (แค่ Direct3DCreate9), DirectSound, WINMM waveOut, XINPUT1_3, WS2_32,
  binkw32.dll (วิดีโอ Bink ปิดซอร์ส -> ต้อง stub/ข้ามบน Android)
- Scaleform GFx (UI) ลิงก์อยู่ใน DLL, มีสคริปต์ Lua ในตัวเกม, .text ราว 14MB
